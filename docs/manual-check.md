# Самостоятельная проверка

1. **Откройте и загрузите примеры.** Перейдите на http://127.0.0.1:8765/ и обновите страницу. В блоке «Пример товара» отметьте манометр и нажмите «Загрузить», затем повторите с термометром. Полные названия должны помещаться в блоке, источник и карточка должны соответствовать выбранному прибору. Само переключение варианта не заменяет введённые данные. Эти действия открывают сохранённые ответы без вызова API.

2. **Проверьте ввод и ошибки.** В форме измените характеристику, добавьте и удалите параметр. Переключитесь в JSON и обратно, изменения должны сохраниться. Удалите название и нажмите «Создать черновик», должна появиться ошибка обязательного поля. В JSON временно удалите закрывающую скобку и повторите, должна появиться ошибка JSON, предыдущая карточка должна остаться. Загрузите пример ещё раз для восстановления правильного ввода.

3. **Запустите реальную генерацию.** Оставьте GPT-6.1 Sol и нажмите «Создать черновик». Появится время ожидания, кнопка повторной отправки станет недоступна. Генерация может занять несколько минут. Во время ожидания можно продолжать просматривать исходные данные. После завершения проверьте заголовок до 70 символов, описание от 800 до 1200, от трёх до пяти запросов и блок для менеджера. Диапазоны в описании должны быть записаны словами, значения в характеристиках должны совпадать с источником. Для отдельной проверки нехватки данных оставьте только название и пустые характеристики с описанием, затем запустите генерацию. Ожидается запрос уточнений и неизвестные значения, для такого ввода допускается короткое описание. Отмена ожидания проверяется отдельным запуском и не гарантирует остановку обработки у провайдера.

4. **Проверьте редактуру и экспорт.** Откройте «Перед публикацией», сверьте пропуски, предупреждения и технические данные. Отметьте редакторскую проверку, затем измените заголовок или описание, отметка должна сброситься, счётчики должны обновиться. Переключите «Просмотр», Markdown и JSON. Текст должен прокручиваться внутри блока, кнопки должны оставаться отдельной строкой после текста. Скопируйте Markdown и JSON, скачайте JSON и откройте его в текстовом редакторе. Экспорт должен содержать текущие ручные правки, характеристики, запросы, блок менеджера и уточнения.

Перед публикацией редактор сверяет текст с источником. Программные тесты, реальные вызовы модели и имитация ошибок API описаны отдельно в [протоколе](verification.md).
