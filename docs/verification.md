# Протокол проверки

Проверка локального приложения на Windows, 3 ноября 2026 года. Результаты программных тестов, браузерных сценариев и реальных генераций имеют разную область доказательности.

## Программные проверки

| Проверка | Результат | Область |
|---|---|---|
| `python -m unittest discover -s tests -q` | 63 теста, OK | Вход, контракт, валидация, защита запроса, обработка API |
| `node --test tests/input.test.mjs` | 14 тестов, OK | JSON, типы, ограничения, дубликаты и нормализация ввода |
| Ruff `E4,E7,E9,F,I` | Пройдено | Ошибки Python, импорты и базовый стиль |
| Ruff format | Пройдено | Форматирование Python |
| Prettier 3.9.10 | Пройдено | JavaScript, HTML и CSS |
| `pip check` в новом окружении | Пройдено | Совместимость установленных runtime-зависимостей |
| Чистый запуск Python 3.12.14 | 10 проверок, OK | Страницы, API, статика и ошибка генерации без ключа |

Мок-ответы провайдера в тестах воспроизводят ошибки авторизации, баланса, лимитов, сети, таймаута, отказа, обрезания и некорректного протокола. Они не доказывают качество модели. [Результат чистой установки](../evaluation/clean-install.json).

Перед публикацией запуск повторён из отдельного Git-клона. Создан новый venv, установлены зависимости из requirements.txt, скопирован .env.example, выполнены 63 теста и 14 проверок запущенного сервера, включая шрифты и оба примера. Проверка проведена на Windows с Python 3.12.14, использован порт 8766, поскольку основной редактор работал на 8765. [Протокол запуска по README](../evaluation/readme-launch.json). Команды macOS и Linux приведены отдельно, на этих ОС запуск не проверялся.

Проверки характеристик включают сохранение точных строк, отрицательных значений, единиц и условий, обнаружение новых чисел, повторяющихся полей и неверного среднего ресурса. Извлечение из паспорта проверяется по буквальному фрагменту. Для описаний отдельно проверяются длина, абзацы, авторская пунктуация и запись диапазонов словами.

## Клиентский путь

В рабочем браузере проверены загрузка двух товаров, явное применение выбранного примера, ввод через форму и JSON, переключение без потери данных, пустое название, неправильный JSON и повторяющиеся ключи. Проверены восстановление ввода после исправления, добавление и удаление параметра, рост многострочного поля и безопасное отображение ссылки источника.

После генерации проверены редактирование текста, счётчики, редакторские предупреждения, сброс подтверждения и пометка устаревшей карточки. JSON скопирован и скачан, содержимое скачанного файла совпало с объектом карточки. Markdown содержит все обязательные блоки. В обоих сырых форматах прокрутка ограничена и панель кнопок расположена после текста.

На отдельном временном стенде с имитацией ответа API проверены ожидание, блокировка повторного нажатия, отмена, изменение данных во время запроса и сохранение ввода и карточки при ошибке API. Платная LLM для этих четырёх сценариев не вызывалась. Стенд не входит в приложение.

Фактические измерения и результаты 21 браузерного сценария сохранены в [browser-checks.json](../evaluation/browser-checks.json). Новое правило применения примера проверено после замены значка обновления на кнопку «Загрузить».

После замены выпадающего списка на два видимых переключателя отдельно проверены сохранение правок до нажатия «Загрузить», применение источника вместе с карточкой и выбор клавиатурой. На 1920×1080, 1365×768 и 390×844 названия помещаются внутри панели и переносятся без горизонтального переполнения. [Результат проверки выбора](../evaluation/sample-picker.json). Повторная оценка модели для этого изменения не проводилась, промпт и генерация не менялись.

## Размеры экрана

Проверены 1920×1080, 1365×768 и 390×844 CSS px. На этих размерах не обнаружены горизонтальное переполнение страницы и обрезанные значения многострочных полей. Текст описания 19 px, значения полей 18 px. Это проверка указанных размеров в одном браузере, а не сертификация доступности или всех устройств.

Снимки рабочего приложения находятся в [previews](../previews). Отдельный [снимок JSON](../previews/json-export.jpg) показывает исправленную панель экспорта.

## Реальные вызовы

[Отчёт модели](model-evaluation.md) и сохранённые записи отделены от мок-тестов. Включены два товара, описание без структурированных характеристик, практически пустой ввод, противоречие и команда внутри источника. Уровень `high` и имя модели указаны как запрошенные параметры посредника.

Один ответ был отклонён проверкой пунктуации. Неудачный результат сохранён в отчёте, исключение не скрывается. Проверка редактором обязательна, автоматические ограничения не доказывают достоверность каждого утверждения.

## Проверка исходников и комплекта

Проверка охватывает активный код, тесты, документацию, примеры и отчёты. Метаданные Git и кэши не входят в комплект. Контроль комментариев Python выполняется токенизатором и AST, комментарии фронтенда проверяются отдельно. Проверяются точное совпадение используемого ключа, похожие ключи провайдера и локальные ссылки документации. [Результат проверки](../evaluation/source-audit.json).

Локальные ссылки позволяют читать документацию в репозитории и архиве.
